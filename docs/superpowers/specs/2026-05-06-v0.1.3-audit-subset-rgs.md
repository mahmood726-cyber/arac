# ARAC v0.1.3 — Tier-P RGS Metrics on v0.1.1 Audit Subset

**Status:** pre-registered (OTS pending)
**Date:** 2026-05-06
**Author:** mahmood726-cyber
**Builds on:** v0.1.1 (Tier-P blinded calibration), v0.1.2 (PMID resolution check)

---

## 1. Goal

Complete the v0.1.1 audit by computing actual RGS (Representation Gap Score) metrics for
the ~16 MAs whose trials were classified by the opus Tier-P production classifier. The
v0.1.1 audit produced trial-level Tier-P verdicts (african_majority / not_african_majority
/ insufficient_data) for 30 trials sampled from 16 unique MAs. This v0.1.3 step groups
those verdicts by MA, computes per-MA RGS metrics using ARAC's existing RGS computation
code, and writes a small atlas CSV. This is the first ARAC atlas containing Tier-P rows.

The trial-level Tier-P classifications in `data/audit_v0.1.1/audit_llm_outputs.json` are
frozen and immutable from v0.1.1; this v0.1.3 spec covers only derivation from those
classifications.

## 3. Output

**File:** `data/audit_v0.1.1/atlas_subset.csv`

One row per (MA, Tier) pair, using ARAC's standard 24-column atlas schema defined in
`src/arac/rgs/csv_writer.py`. Tier column is fixed at `participant` (Tier-P) for all rows
in this atlas. Expected row count: ~16 (one per unique MA in the v0.1.1 sample).

## 4. Computation Method

For each unique MA in the v0.1.1 audit subset:

**Step 1 — Identify trial indices:**
Parse `trial_id` suffix `::t<N>` to recover the 0-based trial index within the MA.
These are the audited trials.

**Step 2 — Identify african_majority subset:**
From `audit_llm_outputs.json`, select audited trials where `tier_p == "african_majority"`.
These form the Tier-P positive subset. Their indices are passed to ARAC's `RGSEngine`.

**Step 3 — Load MA from Pairwise70:**
Use `arac.bridge.load_all_mas()` limited to the RDA files referenced in `sample_list.json`.
This reuses ARAC's bridge to MARecord (which wraps `repro_floor_atlas.loader`).

**Step 4 — Compute RGS via existing engine:**
Call `RGSEngine().compute(record, RGSTier.PARTICIPANT, african_majority_indices)`.

The engine computes:
- **full pooled estimate** — all trials in the MA (via `repool_subset` with all indices)
- **subset pooled estimate** — african_majority trials only (k_subset >= 3 required for
  visibility; k_subset < 3 → `invisible=True`, subset_* fields are None)
- **reproduction_gap** — `|subset_estimate - full_estimate| > 0.005`
- **precision_gap_ratio** — subset CI width / full CI width
- **sign_flip** — subset and full estimates have opposite signs
- **heterogeneity_gap** — `|subset_I² - full_I²| > 0.25`
- **recommendation_change** — subset and full cross different MCID threshold states

**Step 5 — Write CSV:**
Use `write_rgs_rows()` from `src/arac/rgs/csv_writer.py` (same writer as production atlas).

## 7. Risks

**R10 — Audit subset has too few african_majority trials per MA.**
Per v0.1.1 audit results: only 2 trials across the entire 30-trial sample received
`african_majority` verdicts (PMID 9790433 / Ringwald 1998 in MA CD006404__A10, and PMID
21062666 / Tshefu 2010 in MA CD006404__A4). Both MAs belong to review CD006404. This means:
- 14 of the ~16 MAs will have `k_subset=0` → `invisible=True`, no subset estimate
- 1 MA (CD006404__A10) has `k_subset=1` → also `invisible=True` (k < 3 threshold)
- 1 MA (CD006404__A4) has `k_subset=1` → also `invisible=True`

**All ~16 MAs will be invisible under the k>=3 invisibility threshold.** The atlas CSV
will contain full pooled estimates for all MAs but `invisible=True` and `subset_*=None`
for every row. This is the correct and honest output: it documents the baseline for the
visible-MA calculation that will run in v0.2 (larger, more diverse sample).

**R11 — Single-trial african_majority per MA.**
Even if the invisibility threshold is relaxed, pooling a single trial is statistically
degenerate (no between-study variance estimable). ARAC's `repool_subset` returns None
for k_subset < 2. The v0.2 mitigation is sampling MAs with higher expected african_majority
density (e.g., malaria MAs, HIV MAs from sub-Saharan African studies).

**R12 — MA loading coverage.**
The script loads only the 16 .rda files listed in sample_list.json. If a file is missing
or sha256-mismatched, the script logs a warning and marks that MA as load_failed in the
output (does not crash).

## 8. v0.2 Pilot Atlas Notes

v0.1.3 is a calibration step. The substantive v0.2 pilot atlas (n=100 MAs, targeted
sampling toward African-dominant reviews) and v0.3 full atlas (n=6,386 MAs) will produce
the first non-trivially-visible Tier-P RGS rows. This spec and the v0.1.3 script form the
validated compute scaffold for those later runs.
